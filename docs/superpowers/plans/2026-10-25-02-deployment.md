# 阶段二：Compose 与 Swarm 部署 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在已接入节点上完成 YAML 保存部署、Compose/Stack 更新、实际就绪检查、断线结果核对与历史版本重新部署。

**Architecture:** 控制端事务保存应用版本和部署任务，持久化调度记录后发送给 Agent。Agent 先写本地账本，再预检并执行固定 Docker 命令；配置、命令执行结果和真实运行状态分别呈现。

**Tech Stack:** 阶段一 Go/SQLite/WSS/Vue 基础；Docker CLI、Compose v2、Docker 官方 Go SDK、Compose 规范解析库、受限 YAML 解析。

**Spec:** [已批准设计](../specs/2026-10-24-hmoob-dock-design.md)。前置：[阶段一](2026-10-25-01-control-and-agent.md)的公共约束、身份接口与协议。

## Global Constraints

- 单管理员；单机 Docker Compose v2、多节点 Swarm Stack；不引入外部队列或数据库。
- 同一应用同时只能有一个未结束的部署任务；状态待确认仍占锁。
- 单任务已保存输出上限：2 MiB，超限截断并提示。
- 部署执行与就绪等待：分别有可配置期限，默认各 10 分钟；超时不等于 Docker 操作已停止。
- 应用绑定目标与命名空间不可变；请求携带幂等标识和编辑基准版本。
- 凭据与配置遵循阶段一加密/认证约束；固定参数执行，禁止拼接 Shell。
- 不自动创建集群、不构建源码、不自动更新控制端或 Agent、不执行全局 prune、不删除卷。
- 历史操作是“重新部署该版本”，不保证可变镜像标签恢复旧镜像，不恢复业务数据。
- Agent 工作目录与宿主机使用相同绝对路径；外部资源/目录需要预先准备。
- 所有 Task RED/GREEN 使用真实临时 SQLite；真实 Swarm 和浏览器验证是阶段退出门槛。
- 无 Git 初始化/提交/推送授权；只做测试与文件差异检查点。

- [ ] **Step 3: 实现输入边界与显式插值。** 配置正文最多 1 MiB、变量最多 256 个且总计不超过 256 KiB，限制 YAML 深度/别名展开；不执行自定义标签。插值仅查 `cfg.Variables`，支持 Docker 文档语义的 `${VAR}`、默认值/必填语法与 `$$` 转义；未知必需变量报错。保留语义并避免再次插值，将解析后的配置作为固定 payload 使用。

```go
lookup := func(name string) (string, bool) {
    value, ok := cfg.Variables[name]
    return value, ok
}
```

将该 lookup 传给所选 Compose 插值库，不传 `os.LookupEnv`。Compose 完整 schema 与受支持 Swarm profile 分别校验；两者都禁止 `build`、远程 `include`、跨文件 `extends`、活动 profiles。YAML `name` 必须与固定 namespace 一致或缺省，不能重定向应用。

Swarm profile 明确支持现成镜像、command/entrypoint、environment、ports、volumes、networks、healthcheck、configs、secrets、labels、logging、stop_grace_period、deploy 下 replicas/mode/placement/resources/restart_policy/update_config/rollback_config；遇到依赖于 `depends_on`、`container_name`、`restart`、`privileged` 等未支持服务字段的配置返回字段错误，不让 CLI 忽略。顶层允许 version、services、networks、volumes、configs、secrets 和已识别的 `x-` 扩展；只声明外部配置资源时检查对应引用。

对 Compose 明确一次性任务采用平台扩展 `x-hmoob-lifecycle: oneshot`，仅允许服务级 `oneshot` 或缺省；校验后记录到 `OneShotServices`，移除该扩展再交给 Docker。不能仅依据 `restart: no` 猜测任务会正常结束。Swarm 首版只接收 replicated/global 服务，job 模式返回明确不支持。

风险提示至少包含 privileged、host PID/network、Docker socket/敏感宿主机 bind，所有提示须进入预览。RenderedYAML 的 digest 对规范化服务配置、显式变量及应用不可变身份共同计算，不将密码等明文输出到日志。

生成 CLI 输入时，对完成显式插值后的字面 `$` 重新编码为 `$$`，防止 Compose/Stack 二次插值改变密码或命令内容；规范化语义的 digest 在这层 CLI 转义之前计算。通过 `config` round-trip 用例证明 `${literal}` 和 `$$` 最终值不变，不能靠禁止进程环境变量就认为二次插值已解决。

```sql
UPDATE agent_tasks SET execution_started = 1, state = 'running'
WHERE id = ? AND execution_started = 0;
```

RowsAffected 为 1 才获执行权。相同 ID 不同 digest 拒绝；同应用另一个未结束任务拒绝。使用 Agent 进程根 context 而不是 WebSocket context 执行任务；连接断开不直接取消 Docker 子进程。Agent 退出或超时可能已经触发 daemon 操作，账本标记 uncertain 并等待核对。

将阶段一总帧限制升级为 8 MiB，并按类型二次限制：deploy.command 最高 8 MiB（覆盖 JSON 转义膨胀）、inventory 每批仍 1 MiB、控制回执/查询最高 128 KiB、日志片段最高 32 KiB；解码后仍检查 YAML 1 MiB 与变量 256 KiB 业务上限。帧大小不是绕过业务输入上限的方式。
